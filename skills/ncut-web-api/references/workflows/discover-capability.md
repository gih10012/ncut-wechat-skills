# 当前任务的局部探索

1. 先 `knowledge --query`，再解析一个目标服务。目录搜索与个人业务数据是不同任务。
2. `discover SERVICE [--path 已观察页面]` 返回最多 8 个 script/form/链接候选；有相关页面时不要从全站导航开始。`source SERVICE --path 已观察资源 --match 关键词` 最多 3 个词、每词 3 个局部片段，返回资源 SHA256。

JavaScript/JSON 中包含登录分支、登录表单模板或 SSO URL 并不表示当前请求未认证。客户端只对实际 HTML 文档进行登录页识别；源码响应按其代码语义探索，不能据字符串命中再次要求本人登录。
3. 优先用现有本人浏览器会话做一次正常操作，核对实际请求的方法、base URL、body、身份来源、分页和业务成功字段。没有浏览器能力时，仍可做公开页面探索，但不要发明“读取任意浏览器登录态”的命令。
4. 常见中文站点的只读查询会用 POST：查源代码或实际表单语义确认后登记 `effect: read`，无需人为增加写入确认。未知副作用暂不调用。写能力在真正执行前局部复核当前页面/接口证据，不照搬 EaseCation 的 Git SHA 流程。
5. 能力正文保留最小可执行命令、必要字段、正常响应形状、客户端筛选和异常边界。前端可见但没调通是 `source_verified`；请求成功且数据语义符合需求后才写 `runtime_verified` 与时间、证据路径/摘要。
6. 只有跨多步且值得复用时加 workflow：输入、步骤、成功判据、部分结果、停止条件。用意图词挂到能力 `keywords`，用 `workflow` 链接；不预建几十个空能力。

首轮最多 2 个相关资源/约 90 秒。没有新证据时停止当前分支，交付已得结果与最小缺项。用户明确要求调试/继续攻克时再扩大范围；本规则不允许把已授权任务偷偷缩小。
