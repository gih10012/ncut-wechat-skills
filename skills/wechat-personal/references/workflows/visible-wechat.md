# 现有微信窗口读取与操作

CLI 能完成时直接使用 CLI；用户要求窗口操作，或 CLI 缺少能力、确实无法完成当前任务时，使用已安装的 `niri-computer-use` skill 操作本人现有微信窗口。沿用主 SKILL 的发送授权；CLI 提交结果未知时先查看原请求状态和聊天记录，不能直接在窗口重发。接收端不支持的格式不能靠换成窗口操作宣称已解决。

先读取 computer-use 的 SKILL.md，再用 `get_app_state` 查看当前窗口；多窗口时用 `list_windows` 取得精确 ID。在可见界面中选择会话、打开卡片或操作所需控件，每次导航后检查实际结果。不要沿用旧截图的坐标或把输入已送达当作任务完成。niri 的显示电源、亮度保护及输入前后的 session helper 按该 skill 执行。

窗口读取只覆盖实际查看的内容，保留可见日期，不猜未显示的年份、时间或消息。看到小程序通知卡片不等于读到内部业务；打开页面后的实际内容另行核实。登录或二维码页按实际认证需求处理，复用已有登录。

旧的 `python3 "$WX" desktop capture --show` 仅保留为显式截图诊断入口；多个微信窗口时可用 `desktop status` 和 `--window ID`。其 `login_verified:false` 只说明未检查登录。2026-09-14旧快捷键未能确认搜索状态的记录，不是当前computer-use导航的永久禁令；从当前可见控件判断，不继续盲输。

截图、正文及账号信息只保存在本机私有状态，不写入公共技能知识。结束时按computer-use skill恢复显示状态。
