# 朋友圈分页与全部历史

入口为普通安装CLI的`moments`，或`python3 "$WX" native moments`。读取本人账号直接执行，不需发送授权。日常默认按页，只有用户要求全部历史才加`--all`，无需再次询问。

```bash
python3 "$WX" native moments --account me --limit 20
python3 "$WX" native moments --account me --cursor '上一页 next_cursor'
python3 "$WX" native moments --account me --user '精确微信用户ID或唯一完整联系人名称' --limit 20
python3 "$WX" native moments --account me --all
python3 "$WX" native moments --account me --user '精确微信用户ID' --all --include-xml
```

默认20条，`--limit`1..100；游标绑定账号和指定人，不能换范围复用。用户要求读取完整朋友圈时返回未截断正文、媒体引用、位置、当前可见点赞/评论及`details`；只有需要原结构归档才加`--include-xml`。图片/视频引用不是解码后的图片正文，若要看具体媒体内容，在正常窗口打开并实际查看，不推测灰色占位图。

## 加载更新或更早历史

CLI的`--all`读取全部本机已加载条目，没有任意页数截断；它不主动调用远端SNS接口。需要最新或全部可见历史时，继续用已配置的niri-computer-use操作正常微信窗口，不能只返回缓存后宣称完整。读取其SKILL.md，执行显示电源/亮度session保护，用fresh state和精确窗口ID操作。

1. 从现有微信侧栏打开可见的朋友圈入口；指定人则从本人可见的联系人资料/作者资料打开朋友圈相册，核对身份。不要复用旧坐标、会话名猜测或未验证native地址。
2. 读取当前页，再在正确朋友圈窗口滚至已加载末尾触发正常下一页。Linux4.1.13实测`Ctrl+End`可到当前列表末尾并触发加载；每次输入后重新观察。如果当前版本没有该行为，使用可见滚动控件。看到“正在加载”时等待实际完成，网络错误按错误处理。
3. 用CLI读回并按动态`id`去重，保留完整字段和快照时间。需要按页输出可直接用CLI游标，要求全部历史则在窗口加载结束后从头`--all`。已有旧缓存可能超出当前窗口展示范围，标明其缓存来源，不称作本次实时可见。
4. 加载持续到用户指定范围或微信明确的没有更多/可见时间/权限边界。指定人真实出现“朋友仅展示最近一个月的朋友圈”；记录实际提示及置顶旧帖范围。一次空页、缓存数不变、加载超时或网络失败均不能作为完整历史证明。动态流未观察到明确末尾时报告已加载范围，不写“云端全部”。
5. 如果用户任务还要求读取媒体字节，在当前可见详情打开媒体实际查看/保存并单独核验；本命令只读引用，没有新媒体下载/解密功能。结束用实际窗口关闭控件关闭agent新开的只读窗口，不假定桌面快捷键含义；按computer-use skill恢复显示状态。

在本机私有记录中分别保存CLI缓存覆盖、GUI已加载的时间范围和明确末尾证据。正文、作者ID、媒体资源参数与截图不发布。发布/点赞/评论写入不属于本次读取能力。
